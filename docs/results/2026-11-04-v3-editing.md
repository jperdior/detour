# 2026-11-04 (v3): editing tasks

Opus agent, Haiku delegate, policy as in [v2](2026-11-04-v2-budget-notice-ranges.md). Two editing tasks in a private PHP monorepo, each on a 1,350–1,500-line domain aggregate: add a domain method (plus an exception in one case) and unit tests for it. A session passes only if hidden tests (unseen by the agent; verified to fail before and pass after a reference implementation) **and** every existing unit test of that bounded context pass, run in the project's Docker test stack (295–837 tests per check). 5 interleaved reps, 20 sessions.

**All 20 sessions passed.** The per-file budget did not get in the way of editing.

| Task | Claude $ baseline → detour | Change | Turns | Time s | Blocks / targeted reads / delegations per session |
|---|---|---|---|---|---|
| method + exception on a 1,350-line aggregate | 0.582 ± 0.062 → 0.433 ± 0.039 | **−25.6%** | 20.8 → 23.6 | 115 → 114 | 1.0 / 4.4 / **0** |
| method on a 1,500-line aggregate | 0.391 ± 0.078 → 0.370 ± 0.023 | −5.5% (noise) | 12.8 → 16.6 | 70 → 93 | 0.4 / 4.2 / **0** |

## Reading

- **Opus never delegated while editing.** It needs the exact lines it is about to change, so after a whole-file read was denied it switched to Grep plus targeted reads that stayed inside the 350-line budget.
- **The saving came from that switch, not from Haiku.** The baseline read the large file whole; with detour, cache writes fell from 38.7k to 22.5k tokens per session. This matches what haiku-shunt reported: blocking whole reads pushes the agent towards partial reads, and that is where the saving is.
- **For editing, detour's cost is extra turns,** about 3–4 per session, not delegate latency. Wall time was flat on one task and +33% on the other.

## What it suggests

A hook that only blocks whole reads of large files (no delegation, no skill) might capture the editing savings with no latency. That is worth its own variant: **block-only**, compared against baseline and full detour.
